# 기술 스택

- `loom`과 `loom-desktop`은 데몬과 명령에 같은 Rust 라이브러리(`src/lib.rs`)를 쓴다. `loom-desktop`은 인자 없이 열면 GPUI 창을 띄운다.
- 데몬: `tokio`, `axum`, `portable-pty`(Windows ConPTY 포함), `rusqlite`, `rust-embed`, `sysinfo`(중단할 셸의 프로세스 나무), `tokio-tungstenite`(Codex app-server 연결), `typify`(빌드 때 Codex 스키마에서 타입 생성), `ureq`(서버 HTTP), `base64`(OpenCode 계열 Basic 인증)
- 웹 화면은 React, React Flow, xterm.js를 쓴다. 빌드 결과는 데몬 실행 파일에 넣는다.
- [GPUI 앱](데스크톱-앱.md#r469-v2-채팅)은 같은 데몬에 붙어 그래프와 채팅을 그린다.
- API 타입은 Rust에서 한 번만 선언한다. TypeScript 타입은 `ts-rs`로 만든다.
- 데몬 API(경로와 `ts-rs` 타입)의 계약 기준은 `tests/contract/released.txt`다. `tests/contract`가 기준에서 빠지거나 바뀐 것을 막고, 더한 것은 통과시킨다(2026-11-01 사람 결정 Q1965).
- 워크트리와 커밋 그래프는 `git` CLI를 부른다.
- 개발 환경은 배포 환경과 같은 호스트다(「[배포](배포.md#배포)」). 실행 명령은 [AGENTS.md 「개발 환경」](../../AGENTS.md#개발-환경)에 있다.
- 노드를 띄울 때 `LOOM_URL`(노드 문 주소), `LOOM_SPAWN_URL`(데몬 주소), `LOOM_TOKEN`(노드마다 무작위 노드 부분과 실행마다 무작위 실행 부분, 「에이전트 실행」) 환경 변수를 넣는다. SSH 노드는 앞의 두 주소를 받지 않고 노드 접속점(`LOOM_SOCKET`)만 쓴다. 사람이 띄운 셸·명령 노드를 뺀 모든 노드가 `LOOM_TASK_DIR`(「작업 폴더」)도 받는다. 에이전트용 명령은 이 값으로 데몬의 `/api/agent/*`에 HTTP로 요청한다. 데몬은 토큰으로 보낸 노드를 찾는다. 토큰은 노드와 함께 DB에 둔다. 노드 프로세스는 데몬이 다시 시작해도 살아 옛 토큰을 계속 낸다.
- 노드의 `PATH` 앞에 `loom` 명령이 있는 폴더를 넣는다. GPUI 데몬은 데이터 폴더의 `bin`에 `loom` 껍데기를 쓴다. Windows의 `loom.cmd`는 노드 환경의 실행 파일 경로를 읽는다. GPUI 데몬이 띄운 이 PC의 노드는 그 실행 파일로 훅과 CLI를 부른다.
